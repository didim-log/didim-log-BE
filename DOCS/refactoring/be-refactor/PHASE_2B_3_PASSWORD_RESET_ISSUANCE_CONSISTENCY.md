# 비밀번호 재설정 코드 발급 정합성

재설정 코드를 요청할 때마다 새 문서를 쌓던 것을, 회원별 문서 하나를 갱신하도록 바꿨습니다. 보안 난수로 코드를 만들고, 메일 발송이 실패하면 그 코드만 지웁니다.

## 이전과 현재

| 상황 | 이전 | 현재 |
| --- | --- | --- |
| 같은 회원이 여러 번 요청 | 활성 코드가 여러 개 남음 | 회원별 1개, 새 발급이 이전 코드를 대체 |
| 같은 회원 20건 동시 요청 | 최종 코드 수 보장 없음 | 오류 0건, 활성 코드 1건 |
| 다른 회원 코드와 충돌 | 유일 인덱스 오류로 실패 | 새 코드로 다시 시도 (최대 5회) |
| 메일 발송 실패 | 받지 못한 코드가 만료까지 남음 | 그 코드만 삭제, 더 최신 코드는 유지 |
| 코드 생성 | 일반 난수 | `SecureRandom`, 영문 대문자·숫자 8자리 |

로컬 MongoDB 7.0.16에서 확인했습니다.

## 문제

```text
회원 확인 → 난수 코드 생성 → 새 문서 저장 → 메일 발송
```

같은 회원이 여러 번 요청하면 활성 코드가 여러 개 남았고, 동시 요청에서도 최종 코드가 하나라는 보장이 없었습니다. 다른 회원의 코드와 겹치면 유일 인덱스에서 실패했고, 저장 뒤 메일이 실패하면 사용자가 받지 못한 코드가 만료될 때까지 남았습니다.

## 바꾼 내용

```text
회원 확인 → 보안 난수 코드 생성 → studentId 기준 findAndModify(upsert)
→ 메일 발송 → 실패하면 studentId와 코드가 모두 같은 문서만 삭제
```

- 조회 조건은 `studentId`만 써서, 동시 upsert가 회원 유일 인덱스를 따라 한 문서로 모입니다.
- 코드, 만료 시각, 생성 시각을 한 번에 갱신합니다.
- 인덱스는 `resetCode` unique, `studentId` unique, `expiresAt` TTL 세 가지를 보장합니다.

| 상황 | 처리 |
| --- | --- |
| 코드가 다른 회원과 겹침 | 새 코드로 재시도 |
| 동시 upsert의 회원 충돌 | 같은 코드로 재시도 |
| 그 밖의 DB 오류 | 재시도하지 않음 |
| 5회 모두 실패 | 내부 오류, 메일 발송 안 함 |
| 이전 요청의 메일이 늦게 실패 | 더 최신 코드는 유지 |

재설정 코드 값은 로그에 남기지 않고, 충돌 값이 담길 수 있는 MongoDB 예외 객체도 남기지 않습니다.

## 확인한 방법

- 발급 정합성 MongoDB 테스트 9개와 인덱스 계약 테스트 10개가 순차 발급 뒤 문서 1건, 동시 20건 발급 뒤 활성 코드 1건, 충돌 재시도, 5회 소진 시 메일 0건, 메일 실패 뒤 코드 0건, 이전 메일 실패 시 최신 코드 유지를 확인합니다.
- 회원별 중복 문서가 이미 있으면 데이터를 지우지 않고 인덱스 초기화를 실패시킵니다.
- `./gradlew clean check`가 통과했습니다(단위 509개, 통합 84개 중 77개 통과·조건부 7개 제외).

## 남은 한계

- 같은 회원의 동시 요청이 모두 성공하면 메일이 여러 통 갈 수 있고, 마지막에 저장된 코드만 유효합니다. 메일 도착 순서는 보장하지 않습니다.
- SMTP가 메일을 받은 뒤 오류를 돌려주면 메일은 도착했는데 코드는 지워질 수 있습니다. 전달까지 보장하려면 회원별 발급 직렬화나 outbox가 필요합니다.
- 회원별 중복 문서가 있는 운영 데이터는 적용 전에 따로 정리해야 합니다.
