# 문제 상세·언어 부분 갱신

문제 상세나 언어를 저장할 때 문서 전체를 덮어쓰던 것을, 그 작업이 맡은 필드만 `$set`으로 바꾸도록 고쳤습니다. 늦게 끝난 상세 수집이 최신 제목이나 난이도를 예전 값으로 되돌리지 않습니다.

## 이전과 현재

| 확인 항목 | 이전 | 현재 |
| --- | --- | --- |
| 늦은 상세 저장 뒤 최신 메타데이터 | 이전 제목으로 되돌아감 | 제목·분류·난이도·level·태그 유지 |
| 늦은 상세 저장 방식 | 문서 전체 교체 | 상세 5개 필드만 `$set` |
| 언어 감지 실패 | 오래된 값을 다시 저장 | 현재 DB 값 유지 |
| 그사이 삭제된 문제 | 전체 저장으로 다시 생길 수 있음 | 문서 생성 0건 |
| 문제당 저장 연산 | 1회 | 1회 |

로컬 MongoDB 7.0.16에서 "예전 문서 조회, 같은 ID에 최신 메타데이터 저장, 예전 문서로 상세 저장" 순서를 고정해 실행한 결과입니다. 저장 횟수는 같으므로 속도 개선이 아니라 정합성 개선입니다.

## 문제

상세 수집은 대상 문제를 조회하고, BOJ 응답을 그 객체에 복사한 뒤 문서 전체를 저장했습니다.

```text
상세가 없는 문제 조회 → BOJ 상세 수집 → 조회한 객체에 복사 → 전체 저장
```

수집하는 동안 solved.ac 메타데이터 작업이 같은 문제의 제목이나 태그를 바꾸면, 늦게 끝난 상세 작업이 예전 값으로 되돌렸습니다. 상세 새로고침, 언어 갱신, 조회 중 상세 보강에도 같은 전체 저장이 있었습니다.

## 바꾼 내용

### 작업마다 맡은 필드만

| 작업 | 바꾸는 필드 | 건드리지 않는 필드 |
| --- | --- | --- |
| solved.ac 메타데이터 | 제목, 분류, 난이도, level, 태그 | URL, 언어, 상세 |
| BOJ 상세 | 상세 5개 | 메타데이터, URL, 언어 |
| 상세 새로고침 | 상세 5개, 감지에 성공한 언어 | 나머지 |
| 언어 갱신 | 언어 | 메타데이터, URL, 상세 |

상세 5개는 본문, 입력·출력 설명, 예제 입력·출력입니다.

### 부분 갱신 메서드

`ProblemRepositoryCustom`에 두 메서드를 더했습니다.

- `updateDetails`: 상세 5개와 선택적으로 언어만 `$set` 합니다. `findAndModify(returnNew=true, upsert=false)`라서 그사이 지워진 문제를 다시 만들지 않습니다.
- `updateLanguage`: 언어만 `$set` 하고, 일치한 문서가 있었는지 돌려줍니다.

동기·비동기 상세 수집, 상세 새로고침, 언어 일괄 갱신, DB에 없을 때의 문제 생성, 조회 중 상세 보강까지 여섯 경로에서 `save(Problem)`을 없앴습니다.

### 삭제와 겹칠 때

사용자 조회 중 대상이 사라지면 내부 오류 대신 재시도 가능한 409를 돌려주고, 관리자 일괄 작업은 실패 건수로 셉니다.

## 확인한 방법

- 실제 MongoDB 테스트에서 목록 조회 뒤 crawler 응답 직전에 최신 메타데이터를 저장해 순서를 고정했습니다. sleep이나 스레드 순서에 기대지 않습니다.
- 단위 테스트로 여섯 경로의 부분 갱신 호출, 삭제 시 409, 재조회 뒤 중복 수집 방지를 확인합니다.
- 전용 MongoDB·Redis에 연결한 `./gradlew clean check`가 통과했습니다(단위 695개, 통합 172개 중 164개 통과·조건부 8개 제외).

## 남은 한계

- 실제 MongoDB 경합 테스트는 동기 수집 경로만 다룹니다. 비동기 경로는 단위 테스트로 확인했습니다.
- 기존 문서 중 URL이나 언어가 빠진 문서 수는 [고아 데이터 읽기 전용 점검](./PHASE_5C_ORPHAN_DATA_READ_ONLY_DRY_RUN.md)으로 따로 확인합니다.
