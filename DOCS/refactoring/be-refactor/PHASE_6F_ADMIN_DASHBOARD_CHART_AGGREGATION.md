# 관리자 대시보드 차트 집계

관리자 차트가 전체 문서를 읽어 서버에서 날짜별로 묶던 것을, MongoDB가 기간별 개수만 돌려주도록 바꿨습니다. 해결 문제 카드가 0으로 나오던 저장 경로 오류와 중복 집계, 주차 표기 오류도 함께 고쳤습니다.

## 이전과 현재

| 월별 차트 | 이전 반환 문서 | 현재 반환 문서 | 이전 반환 크기 | 현재 반환 크기 |
| --- | ---: | ---: | ---: | ---: |
| 회원 | 240건 | 24건 | 635,160 B | 792 B (99.88% 감소) |
| 해결 문제 | 240건 | 24건 | 635,160 B | 792 B (99.88% 감소) |
| 회고 | 1,200건 | 24건 | 5,176,340 B | 792 B (99.98% 감소) |

| 정합성 | 이전 | 현재 |
| --- | ---: | ---: |
| 해결 문제 카드(기대값 4) | 0 | 4 |
| 해결 문제 일별 차트 마지막 값(기대값 4) | 6 | 4 |
| `2018-12-31`의 주차 | `2018-W01` | `2019-W01` |

로컬 MongoDB 7.0.16에 회원 240명, 회고 1,200건(본문 4,096자), 24개월 데이터를 넣고 MongoDB가 돌려준 문서 수와 크기를 잰 결과입니다. 응답 시간이나 서버 메모리 개선율은 아닙니다.

## 문제

회원 차트에는 가입일만 필요한데 비밀번호와 풀이 배열까지 담긴 회원 문서 전체를 읽었고, 회고 차트도 작성일만 필요한데 최대 5,000자 본문을 함께 읽었습니다.

정합성 문제도 있었습니다.

- 해결 문제 카드가 `solutions.solutions.problemId.value` 경로를 썼지만 실제 저장 경로는 `solutions.items.problemId`였습니다. 성공 풀이가 있어도 카드가 0이었습니다.
- 차트는 같은 문제를 기간 안에서만 중복 제거해서, 다른 날 다시 성공하면 누적값에 여러 번 들어갔습니다.
- 주 번호는 ISO 기준인데 연도는 달력 연도를 써서 `2018-12-31`을 `2018-W01`로 표시했습니다.

## 바꾼 내용

### 지표 기준

| 차트 | 기간별 값 | 마지막 누적값 |
| --- | --- | --- |
| 회원 | 그 기간 가입자 수 | 전체 회원 수 |
| 해결 문제 | 처음 성공한 시점 기준의 고유 문제 수 | 전체 성공 풀이의 고유 문제 수 |
| 회고 | 그 기간 작성된 회고 수 | 전체 회고 수 |

해결 문제는 플랫폼 전체에서 같은 문제를 한 번만 세고, 가장 먼저 성공한 시점에 넣습니다. 그래서 카드와 차트 마지막 값이 같아집니다.

### MongoDB에서 기간별로 집계

```text
회원·회고: 작성일을 기간 문자열로 변환 → 기간별 개수 → 날짜 정렬
해결 문제: 풀이 펼치기 → 성공만 → 문제별 최초 성공 시각 → 기간별 개수 → 날짜 정렬
```

서버는 정렬된 기간별 개수를 누적값으로 바꾸기만 합니다. 기간 문자열은 서버와 같은 시간대(`Asia/Seoul`)로 만들고, 주별 키는 ISO 연도와 주차를 함께 쓰는 `%G-W%V`로 바꿨습니다. 가입일이 없는 이전 회원은 기존처럼 조회 시점에 포함합니다.

## 확인한 방법

- 이전 코드의 조회 방식을 측정 테스트에서 같은 데이터로 재현하고, 실제 MongoDB 명령과 반환 문서를 잡아 크기를 합산했습니다.
- 회원·회고 차트는 이전과 현재 결과가 같았습니다. 해결 문제 차트는 중복 집계를 고친 것이라, 따로 계산한 기준 결과와 현재 결과가 같은지 확인했습니다.
- 변경 전 코드에서 실제 MongoDB 통합 테스트 5개 중 4개가 위 "이전" 값으로 실패했고, 변경 후 모두 통과했습니다. `2021-01-01`이 `2020-W53`으로 나오는 경계도 확인합니다.
- 차트 서비스의 실제 MongoDB 통합 테스트 6개를 더했고, 서비스 코드의 모든 줄과 분기가 실행됩니다.
- 전용 MongoDB·Redis에 연결한 `./gradlew clean check`가 통과했습니다(단위 731개, 통합 205개 중 196개 통과·조건부 9개 제외).

```bash
./gradlew integrationTest --tests '*AdminDashboardChartIntegrationTest'
```

## 남은 한계

- 전체 기간 누적값이 필요해서 MongoDB는 여전히 컬렉션 전체를 검사합니다. 줄어든 것은 돌려받는 데이터와 서버의 객체 생성입니다.
- 해결 문제가 크게 늘면 MongoDB 집계의 메모리 사용을 따로 확인해야 합니다.
- "오늘 가입", "오늘 회고" 카드는 지금 FE 계약상 전체 누적 차트를 엽니다.
