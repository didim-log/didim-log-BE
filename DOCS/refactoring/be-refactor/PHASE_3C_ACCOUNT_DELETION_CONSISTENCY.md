# 계정 삭제 경로 통합과 연관 데이터 정리

본인 탈퇴와 관리자 강제 탈퇴가 서로 다른 코드로 서로 다른 데이터를 지우던 것을 하나의 삭제 흐름으로 합치고, 남던 사용자 데이터까지 정리하도록 바꿨습니다.

## 이전과 현재

| 데이터 | 이전: 본인 탈퇴 | 이전: 관리자 삭제 | 현재: 두 경로 공통 |
| --- | --- | --- | --- |
| 회원 | 삭제 | 삭제 | 마지막에 삭제 |
| 회고, 피드백 | 삭제 | 남음 | 삭제 |
| 풀이 로그(회원 ID 있음) | 남음 | 남음 | 삭제 |
| 사용자 템플릿 | 남음 | 남음 | 삭제 |
| 비밀번호 재설정 코드 | 남음 | 남음 | 삭제 |
| Refresh Token | - | - | 전체 폐기 |
| 시스템 템플릿, 관리자 감사 로그 | 보존 | 보존 | 보존 |
| 관리자 삭제 감사 기록(`USER_DELETE`) | - | 기록 안 됨 | 기록 |

## 문제

본인 탈퇴는 회고와 피드백을 지웠지만 관리자 삭제는 회원 문서만 지워서, 같은 계정이어도 삭제 방법에 따라 결과가 달랐습니다. 두 경로 모두 풀이 로그, 사용자 템플릿, 비밀번호 재설정 코드를 남겼습니다. `USER_DELETE` 감사 유형은 선언만 되어 있고 실제 삭제 API에서 기록하지 않았고, API 문서에는 같은 학생의 다른 작업과 겹칠 때의 409와 Redis 장애 시 503이 빠져 있었습니다.

## 바꾼 내용

`AccountDeletionService` 하나가 두 경로의 삭제를 맡습니다.

```text
학생 ID별 잠금 획득 → 잠금 안에서 회원 최신 조회
→ Refresh Token 전체 폐기 → 비밀번호 재설정 코드 삭제
→ 회고·피드백·사용자 템플릿·회원 ID가 있는 로그 삭제
→ 회원 문서를 마지막에 삭제
```

- Refresh Token 폐기 중 Redis 오류가 나면 503을 돌려주고 MongoDB 삭제를 시작하지 않습니다.
- 중간에 실패하면 회원 문서를 남깁니다. 각 삭제는 다시 실행해도 안전해서 같은 요청을 재시도하면 남은 데이터가 정리됩니다.
- 관리자 삭제가 성공하면 `USER_DELETE`, 대상 회원 ID, 요청 IP를 감사 로그로 남깁니다.
- 회원 ID가 없는 이전 로그는 BOJ ID만으로 주인을 판단할 수 없어 지우지 않습니다. BOJ ID는 바뀌거나 다른 계정이 쓸 수 있기 때문입니다.
- 사용자별 삭제가 컬렉션 전체를 훑지 않도록 `feedbacks.writerId`, `templates.studentId` 인덱스를 더했습니다.

| 상황 | 응답 |
| --- | --- |
| 회원 없음 | 404 `STUDENT_NOT_FOUND` |
| 같은 학생의 다른 상태 변경과 잠금 충돌 | 409 `SESSION_STATE_CONFLICT` |
| 세션 저장소 사용 불가 | 503 `SESSION_STATE_UNAVAILABLE` |

## 확인한 방법

- 단위 테스트로 삭제 순서, 회원이 없을 때 아무것도 지우지 않음, Redis 실패 시 MongoDB 삭제 0건, 중간 실패 시 회원 보존과 재시도 완료, 감사 기록 성공 시 1회·실패 시 0회를 확인합니다.
- 로컬 MongoDB 7.0.16에서 본인·관리자 경로 각각, 대상 데이터만 지워지고 시스템 템플릿과 다른 학생 데이터, 회원 ID 없는 이전 로그가 남는지 확인했습니다.
- 전체 `./gradlew clean check`가 통과했습니다(단위 653개, 통합 146개 중 139개 통과·조건부 7개 제외).

## 남은 한계

- 여러 컬렉션 삭제 중 프로세스가 멈추면 앞서 지운 데이터는 이미 지워진 상태로 남습니다. 완전한 원자성이 필요하면 replica set 트랜잭션이나 삭제 상태 관리가 필요합니다.
- 삭제 전에 시작한 사용자 쓰기가 삭제 뒤에 끝나 고아 문서를 만드는 문제는 [계정 삭제와 사용자 데이터 쓰기 경합 차단](./PHASE_3D_ACCOUNT_WRITE_BARRIER.md)에서 막았습니다.
- 일일 AI 사용량 키와 OAuth 교환 코드는 짧게 만료되므로 즉시 지우는 대상에 넣지 않았습니다.
