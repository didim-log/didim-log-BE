# 기본 템플릿 참조 정합성

기본값으로 쓰던 템플릿을 지우면 회원 문서에 지워진 ID가 남던 문제를 고쳤습니다. 템플릿을 지우기 전에 기본값 참조를 먼저 해제하고, 목록과 기본값 조회가 같은 기준으로 기본 템플릿을 판단하게 했습니다.

## 이전과 현재

| 상황 | 이전 | 현재 |
| --- | --- | --- |
| 기본 템플릿 삭제 뒤 회원 문서 | 지워진 ID가 남음 | 성공·실패 기본값 참조 0건 |
| 지워진 ID가 남은 상태의 기본값 조회 | 시스템 템플릿으로 대체 | 시스템 템플릿으로 대체 |
| 같은 상태의 템플릿 목록 | 기본 템플릿 표시 없음 | 기본값 조회와 같은 시스템 템플릿 표시 |
| 계정 삭제 중 실패해 회원이 남음 | 지워진 사용자 템플릿을 가리킴 | 사용자 템플릿 참조는 해제, 시스템 참조는 유지 |
| 다른 사용자의 템플릿 수정·삭제 | 응답이 문서와 다름 | 403 `ACCESS_DENIED`로 통일 |

## 문제

기본값으로 지정한 사용자 템플릿을 지우면 `templates` 문서는 없어지지만 회원의 `defaultSuccessTemplateId`나 `defaultFailTemplateId`에는 지운 ID가 남았습니다. 그 뒤로 기본값 조회는 시스템 템플릿으로 대체하는데, 템플릿 목록은 남은 ID를 그대로 써서 기본 템플릿을 표시하지 않았습니다. 계정 삭제가 템플릿을 지운 뒤 중간에 실패해도 같은 상태가 됐습니다.

## 바꾼 내용

### 템플릿 삭제 순서

학생별 잠금 안에서 처리합니다.

1. 회원과 지울 템플릿을 다시 조회합니다.
2. 시스템 템플릿이나 다른 사용자의 템플릿이면 거절합니다.
3. 이 템플릿을 쓰는 기본값 필드를 고릅니다.
4. 그 필드만 조건부로 해제합니다.
5. 템플릿을 지웁니다.

```text
조건: _id = studentId AND 해당 기본값 필드 = 지울 템플릿 ID
갱신: $unset 해당 필드, $inc documentVersion
옵션: returnNew=true, upsert=false
```

조건이 맞지 않으면 템플릿을 지우지 않고 409를 돌려줍니다. 참조를 먼저 해제하므로, 템플릿 삭제가 실패해도 회원이 없는 템플릿을 가리키는 상태는 생기지 않습니다.

### 계정 삭제

기본값이 시스템 템플릿이면 그대로 두고, 사용자 템플릿이거나 이미 없는 ID면 해제한 뒤 사용자 템플릿을 지웁니다.

### 목록과 기본값 조회를 같은 기준으로

템플릿 목록은 실제로 목록에 있는 ID만 사용자 기본값으로 인정하고, 아니면 기본값 조회와 같은 시스템 템플릿을 씁니다. 과거 데이터에 깨진 ID가 있어도 두 API가 다른 템플릿을 기본값으로 보여주지 않습니다.

## 확인한 방법

- 실제 MongoDB 7.0.16·Redis 7.2.5에서 기본 템플릿 삭제 뒤 참조 0건, 템플릿 삭제 실패 시 템플릿은 남고 참조는 0건, 기본값 설정 중 삭제 409와 재시도 성공, 계정 삭제 중간 실패 시 사용자 참조만 해제되는 것을 확인했습니다.
- 단위 테스트로 기본값이 아닌 템플릿 삭제 시 회원 갱신 없음, 두 기본값이 같은 템플릿일 때 함께 해제, 조건 불일치 409, 다른 사용자 템플릿 403을 확인합니다.
- 전체 `./gradlew clean check`가 통과했습니다(단위 675개, 통합 156개 중 149개 통과·조건부 7개 제외).

## 남은 한계

- 두 컬렉션을 묶는 트랜잭션은 아닙니다. 참조 해제 뒤 템플릿 삭제가 실패하면 템플릿은 남고 기본값 선택만 풀립니다.
- 과거 회원 문서에 남은 깨진 ID를 일괄 수정하지는 않았습니다. 읽기 응답만 통일했고, 저장값 정리는 운영 데이터를 확인한 뒤 따로 해야 합니다.
