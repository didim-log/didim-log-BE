# 유지보수 설정 원자화

Redis 네 키에 나눠 저장하던 점검 모드 설정을 JSON 한 키로 합쳤습니다. 점검이 끝났는데도 요청을 계속 막거나, 두 관리자의 설정이 섞이던 문제를 없앴습니다.

## 이전과 현재

| 상황 | 이전 | 현재 |
| --- | --- | --- |
| 종료 시각이 지난 뒤 | `endTime`만 사라지고 `enabled=true`가 남아 계속 차단 | 키 전체가 만료돼 차단 해제 |
| 두 관리자가 동시에 설정 | 한 요청의 시작 시각과 다른 요청의 공지 ID가 섞일 수 있음 | 둘 중 완전한 설정 하나만 보임 |
| 만료 확인 중 새 설정 저장 | 조회 쪽 삭제가 새 설정까지 지울 수 있음 | 조회는 키를 지우지 않음 |
| 유한 설정을 무기한으로 변경 | - | 기존 만료 시간이 제거되고 새 설정 유지 |

## 문제

점검 설정은 네 키에 나뉘어 있었습니다.

```text
maintenance:enabled
maintenance:startTime
maintenance:endTime
maintenance:noticeId
```

종료 시각 키에만 만료 시간이 있어서, 시간이 지나면 `endTime`은 사라지고 `enabled=true`만 남을 수 있었습니다. 이 상태는 종료 시각 없는 점검처럼 읽혀 점검이 끝난 뒤에도 일반 요청을 막았습니다.

저장과 조회도 여러 명령으로 나뉘어, 동시에 바꾸면 서로 다른 요청의 값이 섞여 보였고, 만료를 확인한 조회가 키를 지우는 사이 새 설정이 들어오면 그것까지 지웠습니다.

## 바꾼 내용

### 설정과 만료를 한 키에

활성 여부, 시작·종료 시각, 공지 ID를 JSON으로 묶어 `maintenance:config`에 저장합니다.

- 종료 시각이 있으면 `SET ... PX`로 본문과 만료를 함께 씁니다.
- 종료 시각이 없으면 만료 없이 씁니다.
- 끄거나 이미 지난 종료 시각을 받으면 점검 키를 모두 지웁니다.

새 설정 저장과 기존 네 키 삭제는 Lua 한 번으로 처리해서, 새 설정이 만료된 뒤 예전 `enabled=true`가 다시 드러나지 않습니다.

### 한 번에 읽기

새 키와 기존 네 키를 `MGET` 한 번으로 읽습니다. 새 키가 있으면 항상 새 키만 씁니다. 조회는 키를 지우지 않고 만료는 Redis에 맡깁니다.

### 기존 키에서 옮기기

새 키가 없으면 기존 `enabled`가 정확히 `true`인 설정을 읽고, 종료 시각이 지났으면 꺼진 것으로 응답합니다. 다음 관리자 저장 때 새 키로 옮기면서 기존 키를 지웁니다.

## 확인한 방법

로컬 Redis 7.2.5의 전용 DB에서 확인했습니다.

| 조건 | 결과 |
| --- | --- |
| 종료 시각이 있는 설정 | 저장 직후 활성, 종료 뒤 키 없음·비활성 |
| 유한 설정을 무기한으로 변경 | 만료 시간 제거, 새 설정 유지 |
| 기존 네 키만 있을 때 | 종료 시각과 공지 ID를 그대로 반환 |
| 기존 값 교체 | 기존 네 키 제거, 새 키 만료 뒤 다시 켜지지 않음 |
| 두 writer와 두 reader 동시 실행 | 섞인 설정 0건 |

## 남은 한계

- 기존 데이터에서 `enabled=true`이고 `endTime`이 없으면, 원래 무기한인지 종료 시각만 만료된 것인지 구분할 수 없습니다. 임의로 끄지 않도록 무기한으로 읽으므로 운영 전환 전에 직접 확인해야 합니다.
- 이전 버전은 새 키를 읽지 못해서 섞어 돌리거나 이전 버전으로 되돌리려면 이중 쓰기가 필요합니다.
- Lua와 `MGET`은 단일 Redis 기준입니다.
