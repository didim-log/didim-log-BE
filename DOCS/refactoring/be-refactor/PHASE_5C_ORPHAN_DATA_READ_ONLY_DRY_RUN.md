# 고아 데이터 읽기 전용 점검

탈퇴한 회원을 가리키는 기록처럼 과거에 남았을 수 있는 고아 데이터를, 아무것도 지우지 않고 읽기 권한만으로 세는 점검 도구를 만들었습니다.

## 이전과 현재

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| 기존 고아 데이터 확인 | 확인 방법 없음 | 읽기 전용 점검으로 관계 7개 확인 |
| 운영 DB 접근 권한 | - | `read` 역할 하나와 TLS만 허용 |
| 점검 중 데이터가 바뀜 | - | 전후 문서 수·필드 지문이 다르면 `BLOCKED`로 중단 |
| 점검 결과의 의미 | - | 검토 자료일 뿐 삭제를 승인하지 않음 (`cleanupAuthorized: false`) |

계정 삭제와 사용자 쓰기 경합을 막아 새 고아 데이터는 생기지 않게 했지만([계정 삭제와 사용자 데이터 쓰기 경합 차단](./PHASE_3D_ACCOUNT_WRITE_BARRIER.md)), 이미 남은 데이터는 자동으로 지우지 않습니다. 지우기 전에 무엇이 남았는지 안전하게 세는 단계입니다.

## 점검 범위

| 구분 | 참조 | 확인 내용 |
| --- | --- | --- |
| 사용자 소유 | 회고 → 회원 | 소유자 없음, 값 누락, 형식 오류 |
| 사용자 소유 | 피드백 → 회원 | 소유자 없음, 값 누락, 형식 오류 |
| 사용자 소유 | 사용자 템플릿 → 회원 | 소유자 없음, 값 누락, 형식 오류 |
| 사용자 소유 | 로그 → 회원 | 값이 있는 로그의 소유자 없음, 형식 오류 |
| 사용자 소유 | 비밀번호 재설정 코드 → 회원 | 소유자 없음, 값 누락, 형식 오류 |
| 기본 참조 | 회원의 기본 성공·실패 템플릿 → 템플릿 | 대상 없음, 다른 사용자의 템플릿, 대상 형태 오류 |

시스템 템플릿, 회원 ID가 없는 과거 로그, 관리자 감사 로그는 삭제 후보로 보지 않습니다. BOJ ID로 소유자를 추정하지도 않습니다.

## 안전 장치

다음 경우에는 결과를 `BLOCKED`로 남기고 멈춥니다.

- 대상 DB 이름이 다르거나 예약 DB를 가리킴
- 계정에 `read` 외의 권한이 있음
- 같은 ID가 문자열과 ObjectId로 함께 있어 어느 문서인지 정할 수 없음
- 점검 전후 문서 수나 점검 필드 지문(SHA-256)이 달라짐

조회는 primary와 majority read concern으로 하고, 보고서에는 원본 회원·템플릿 ID를 쓰지 않습니다. 코드에 쓰기 메서드와 `$out`, `$merge`가 없는지도 정적으로 검사합니다.

## 확인한 방법

만든 데이터(운영 데이터가 아님)로 MongoDB 7.0.16 임시 컨테이너에서 확인했습니다.

| 확인 항목 | 기대값 | 결과 |
| --- | ---: | ---: |
| 소유자 없는 문서 | 6건 | 6건 |
| 대상 없는 기본 템플릿 참조 | 1건 | 1건 |
| 다른 사용자 템플릿 참조 | 1건 | 1건 |
| 쓰기 요청 | 0건 | 0건 |
| 반복 실행 결과와 데이터 지문 | 같음 | 같음 |
| 과도한 권한 / ID 충돌 | 차단 | 차단 |

```bash
ORPHAN_DRY_RUN_EXPECT_CLEAN_SOURCE=true performance/orphan-data/verify-dry-run.sh
```

운영 데이터는 삭제 권한이 없는 전용 계정과 TLS 주소로만 점검하고, 자격 증명은 저장소에 남기지 않습니다.

## 남은 한계

- 여러 조회가 하나의 DB snapshot을 공유하지 않습니다. 보고서에도 `snapshotGuaranteed: false`로 적습니다.
- "발견하지 못함"은 점검한 범위에서 못 찾았다는 뜻이지 전체 무결성을 보장하지 않습니다.
- 후보 크기 합계는 BSON 논리 크기라서 실제로 되찾는 디스크 용량이 아닙니다.
- 이 도구는 삭제를 실행하지 않습니다.
